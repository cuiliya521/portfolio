## Contracts and preserved rules

`createBudget` still exposes the same methods, price policy and authorization
objects. Its validation, grant, availability and public operation blocks are
byte-identical to R5-0A (checked by `validation/r5-0d/invariants.mjs`).

Without `storage`, the extracted file backend preserves path locks, symlink
checks, fsync, external-anchor requirement and legacy dry-wire fixtures. A
local `.anchor` still cannot authorize live requests.

The optional host-injected storage contract is:

```
{ identityPath, accountId, hasTrustedControl,
  transaction(async ({state, anchor, assertOwned, commit}) => result) }
```

`commit(state,anchor)` stages both; `transaction` returns only after durable
COMMIT is acknowledged. This replaces the old file-plus-anchor boundary for
PostgreSQL, NOT the budget rules. Legacy `trustedControl.transaction` continues
to work with the file backend; it is not silently used as a cloud file mirror.
Never accept a storage object, pool, accountId, price, grant or database URL
from a model/tool/client. These are trusted operator/server configuration.

```
const storage = createPostgresBudgetStorage({
  pool: restrictedServerPool, accountId: fixedOperatorAccount,
  identityPath: '/cui-budget/fixed.json'
});
const budget = createBudget({mode: 'live', accountId: fixedOperatorAccount, storage});
```

This example grants NO permission to initialize or spend. No connection string,
real credential or live pool is configured in this repository. No runtime npm
package or deployment configuration was added. The adapter uses an injected
pg-compatible client. Later driver selection/lockfile creation is a separate
approved environment setup step.

## PostgreSQL design and operator migration

`sql/001-budget.sql` is for a NEW, isolated PostgreSQL database, never the
NoteGuard database or website Production. It has NOT been executed here.
Applying it needs an administrator able to create roles/schema and set the
owner role; inability to do so is a blocker, not a reason to use an admin
connection in the runtime. Do not auto-install it on app startup.

- `accounts`: immutable account/login/ledger/path/initialization binding;
  operator-approved config, price version/digest/rates/expiry, reservations,
  limits, initialized flag, revision and authoritative ledger+anchor text.
- `batch_grants`: exact operator-approved normalized grants; runtime cannot
  add grants, reset the account, change price or widen permissions.
- `audit`: one append per successful revision, previous/new digest and full
  synthetic ledger snapshot. No prompts, Key, connection string or raw API
  headers are stored. Runtime has no table INSERT/UPDATE/DELETE/TRUNCATE rights.
- `lock_snapshot` and `commit_snapshot`: SECURITY DEFINER routines, fixed
  search_path, PUBLIC execution revoked, bound to actual `session_user`.
  The runtime role is a NOLOGIN permission group. A separate SQL-created
  low-privilege LOGIN role inherits ONLY that group; bind it to one account.
  Do not inject Neon owner/superuser or management API credentials into the app.

Operator provisioning (not implemented as a public endpoint): review history,
provision one fixed account row and its initial grant, set enabled/expiry,
and issue the frozen explicit initialization object. Use the same account for
new batches and deployments; never branch/clone/reset the budget database per
Git branch. Nonzero history cannot use the empty-ledger initializer; stop for
reviewed recovery tooling. Registration, grant approval and recovery credentials
remain separate from runtime. Database owner/cloud administrator remains trusted;
this design does not claim to resist a malicious owner restoring the database.

The PostgreSQL adapter holds one connection/row lock per short budget operation,
then updates state+anchor+audit in ONE transaction. Model HTTP execution must be
outside it, after permit consumption has committed. No in-memory global lock,
local path, deployment ID or TTL cache is an authority. JSON remains TEXT so
PostgreSQL JSONB key ordering does not break frozen SHA256 serialization.

A lost COMMIT acknowledgement returns `budget_commit_uncertain`; no ticket is
returned, no retry is made. Reconciliation is required before resuming: if the
commit occurred, its unresolved reservation stays charged; if not, no model
request was authorized. This deliberately favors safe stopping over availability.

## Cloud handler differences (NOT implemented)

The unchanged localhost server listens only on 127.0.0.1 and checks exact
localhost Host/Origin; it keeps sessions, request fingerprints, active
AbortControllers and navigation proposals in process memory. Do NOT remove
these checks to deploy it.

A future independent `/api/cui-lab/*` handler needs verified Preview protection,
server-side exact origin/host checks, Secure HttpOnly same-site session/CSRF,
shared persistent request/proposal status with atomic confirmation, cancellation
semantics across instances, and secret-free error/log output. AbortController
itself cannot migrate between instances. Keep one whole model turn in one
invocation; if it dies, unresolved budget stops future calls. Do not serialize
or recreate process-local permit objects across requests. Shared cancellation
needs a persisted flag checked before every dispatch and final response; a flag
cannot guarantee stopping a supplier request already in flight.

Expose only the isolated test UI/static allowlist, never server/SQL/knowledge
files from a broad repository static root. Preserve 16 approved / 10 pending,
source binding and confirmed navigation. No prototype injection into seven pages.
