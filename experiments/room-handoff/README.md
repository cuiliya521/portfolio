# CUI × 盘古｜双场景自然交接 R0（隔离实验）

## 唯一命题
原版梦幻 Workspace → 点击盘古项目入口 → 通过锚定该卡片的一次视口遮罩揭示真正的六字段工作台 → 进行一次真实字段选择 → 原方向退出 Workspace。

**并不是「缩略截图放大」**：遮罩揭示的是预加载的整页 HTML，字段为可操作表单；未把任何截图当成互动产品。Work 浏览器必须实际核实中途视觉，不能仅信此说明。

## 基线与范围
- 分支：`experiment/cui-room-handoff-r0`，从 `fix/cui-job-ready-r1-20261024` 创建。
- 正式主分支 `main`、正式站与原版首页/Workspace/盘古默认入口不变。
- 仅加 `?handoff=1` 会使用新交接；不带参数保持原入口及现有行为。
- 六字段和唯一经核实的可选值「清爽明亮」延续 B1；冻结 CUI 角色引用 `assets/pangu-r1/cui-pointing.png`，与 B1 中引用角色 SHA-256 一致。
- 归档海报不提前展示；本轮只验证**进入—字段操作—返回**，没有实时生图。
- 工作台使用 B1 的信息结构和状态逻辑，放在独立的清晰产品环境；没有重新设计原梦幻背景。

## 技术实现
- `room-handoff.js/css`：通过原 Workspace 卡片触发；浏览器 history 增加可退回的一步；原位 circular reveal（只揭示真实 DOM、无图片缩放）；反向关闭，焦点回原入口；支持 Esc、Back/Forward、重复进入；低动效直接切场景。
- `index.html`：仅新增实验文件引用，老控制器不改。
- `experiments/room-handoff/index.html + room.css + room.js`：真实六字段工作台；展开 → 选择 → 确认 → 收回，撤销、修改、重来及返回；不是生产系统。
- 若子页面无法完成 ready 握手，则保持旧 Workspace 可见；交接超时后恢复原版盘古入口，避免访客被卡死。

## QA 实施与证据要求
请在 Work 的真实云浏览器从完整站点打开 `?handoff=1#cui-workspace`，分别检查：
1. 桌面 1363×936 和手机 390×844：主页→Workspace→盘古是否存在闪白/遮挡/可视跳跃，导览与全页视觉是否自然衔接。
2. 字段：展开、选择、确认、收回、修改、撤销、再次确认，均有可见状态与键盘焦点。
3. 退出：顶部返回、Esc、浏览器 Back/Forward、重复进入；返回仍指向原盘古项目卡，Workspace 滚动不会锁死。
4. 禁用实验参数：原盘古路径仍然可用，不被遮罩篡改。
5. 真机触控、prefers-reduced-motion、Console 错误、网络错误。
6. 保存**无剪辑动态录像**与固定视口开始/遮罩中段/结束/退出关键帧；Impeccable 独立评估自然度、审美和视觉记忆点。
